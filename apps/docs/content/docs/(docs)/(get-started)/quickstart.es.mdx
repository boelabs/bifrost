Esta guía te permite ejecutar un gateway local, conectar un deployment de OpenAI llamado `general` y crear una virtual key para tu aplicación. Si ya tienes un gateway en funcionamiento, comienza con [Tu primer deployment](/es/docs/first-deployment).

## Antes de empezar [#before-you-start]

Instala Bun 1.4+ y Docker Compose. Necesitas una API key de OpenAI con acceso al modelo del ejemplo. Los comandos de Compose ejecutan Postgres 18 y Redis 8 en tu equipo.

<Callout type="warn" title="Mantén privadas las credenciales del operador">

La **master key** permite administrar Bifrost. La **API key del proveedor** autentica al gateway ante ese proveedor. Tu aplicación recibe una **virtual key** distinta; no le entregues ninguna de las credenciales del operador.

</Callout>

<Steps>
<Step>

## Ejecutar el gateway [#run-the-gateway]

```bash
git clone https://github.com/boelabs/bifrost.git && cd bifrost
bun install
docker compose -f docker/compose.yaml -f docker/compose.local.yaml up -d postgres redis
```

Crea `apps/gateway/.env` a partir de `apps/gateway/.env.example` e incluye estos valores:

```bash
PORT=4000
NODE_ENV=development
MASTER_KEY=replace-with-at-least-32-random-characters
ENCRYPTION_KEYRING={"primary":"64_hex_chars_32_bytes"}   # value: openssl rand -hex 32
ACTIVE_ENCRYPTION_KEY_ID=primary
DATABASE_URL=postgres://gateway:gateway@localhost:5432/bifrost
REDIS_URL=redis://localhost:6379
```

Aplica las migraciones e inicia el gateway:

```bash
bun run --filter @boelabs/bifrost db:migrate
bun run --filter @boelabs/bifrost dev
```

Confirma que está activo:

```bash
curl http://localhost:4000/health/ready   # 200 once Postgres + Redis + extensions are healthy
```

Para el resto de esta página:

```bash
export BASE=http://localhost:4000
export MASTER_KEY=replace-with-at-least-32-random-characters
```

</Step>
<Step>

## Registrar un deployment [#register-a-deployment]

Un **deployment** conecta un public model con un adapter, un modelo upstream y sus credenciales. Créalo con la master key. La API key del proveedor se envía en el cuerpo y se almacena cifrada:

```bash
curl -X POST $BASE/admin/deployments \
  -H "Authorization: Bearer $MASTER_KEY" -H "content-type: application/json" -d '{
    "publicModel": "general",
    "adapterKey": "openai",
    "upstreamModel": "gpt-5.5",
    "credentials": { "apiKey": "sk-..." }
  }'
```

`general` ya es un public model. Para inspeccionar las operaciones y los transports **antes de guardar**, utiliza el mismo cuerpo en `POST /admin/deployments/resolve`.

</Step>
<Step>

## Crear una virtual key [#issue-a-virtual-key]

Crea una virtual key para la aplicación. `allowedModels` limita los public models permitidos (`[]` o un valor omitido permite todos):

```bash
curl -X POST $BASE/admin/keys \
  -H "Authorization: Bearer $MASTER_KEY" -H "content-type: application/json" -d '{
    "name": "my-app",
    "allowedModels": ["general"]
  }'
```

La respuesta muestra el secreto **una sola vez**. Guárdalo antes de continuar:

```json
{ "data": { "id": "…", "keyPrefix": "sk-abcdefg", "key": "sk-…", "allowedModels": ["general"] } }
```

Consulta [Virtual keys](/es/docs/virtual-keys) para configurar presupuestos, límites de RPM/TPM y rotación.

</Step>
<Step>

## Realizar una solicitud [#make-a-call]

Utiliza el nombre público en `model` y la virtual key obtenida en el paso anterior.

<Tabs items={["curl", "Python"]}>
<Tab value="curl">

```bash
curl -X POST $BASE/v1/chat/completions \
  -H "Authorization: Bearer sk-..." -H "content-type: application/json" -d '{
    "model": "general",
    "messages": [{ "role": "user", "content": "Say hello in one word." }]
  }'
```

</Tab>
<Tab value="Python">

Instala el SDK con `pip install openai`.

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:4000/v1", api_key="sk-...")
resp = client.chat.completions.create(
    model="general",
    messages=[{"role": "user", "content": "Say hello in one word."}],
)
print(resp.choices[0].message.content)
```

</Tab>
</Tabs>

Una respuesta correcta contiene el mensaje del asistente en `choices[0].message.content`. Si falla, comprueba el nombre del modelo, los permisos de la virtual key y las credenciales del proveedor.

La misma key y URL base sirven para `/v1/responses`, `/v1/messages` (formato de Anthropic), `/v1/embeddings`, `/v1/images/*` y `/v1/audio/transcriptions`. Cada respuesta incluye `x-request-id`. Las solicitudes realizadas con virtual keys limitadas también incluyen headers `x-ratelimit-*`.

</Step>
